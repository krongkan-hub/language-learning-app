## Status

The project is a CLI language-learning roleplay application using local LLMs via MLX on Apple Silicon for English and Japanese instruction.

There are now **two front ends** — the CLI and a local web UI (`make web`) — over one session engine.

Re-measured **2026-09-13**: the deterministic gate is green at 487 tests, and all five LLM-graded suites are above their baselines (coach 85.8%, judge 93.3%, actor 87.0%, moods 100.0%, coachreason 100.0%). `coachreason` is new — it reads the bracketed reason beside a correction, which no suite had ever looked at.

**A caution about this table's honesty, learned on 2026-09-13.** Twelve rows below still read "Open" while the fix for each was already merged, some for a week. Anyone picking work off this file would have started on something already done. The rows are now reconciled against the code, and the one that could not be re-verified by inspection (OPEN-34) says so instead of being flipped. Re-check status against `app/` before trusting a row, and update the row in the same commit as the fix.

The headline number to read is still the coach's, now **85.8%**. The remaining gap is **under-correction, not over-correction**: measured on 2026-09-13 across twelve clear English errors the fixtures never covered, recall was **25/60** while the clean control held at 40/40. Past tense read **0/15**. See OPEN-10 — the same shape in Japanese — and this is still the largest known quality gap in the product.

**Read the 99.5% narrowly.** The playtest measures *task completion* — whether a simulated learner can get the NPC to the goal, graded by the judge. It says nothing about whether the learner's language was corrected, so it is blind to the coach by construction. "99.5% of tasks are winnable" and "the coach misses ~3/4 of Japanese errors" (OPEN-10) are both true at the same time, and only the first one looks like a headline. Nothing in the suite table above measures whether a learner actually improves.

No fixture was deleted, reworded, or relabelled to reach these numbers. [`dev/fixtures/eval_baselines.json`](dev/fixtures/eval_baselines.json) floors each suite below its measured score, because every suite samples only a handful of iterations and a single flaky run is normal — the actor read 96 / 98 / 99 per 100 across three consecutive runs with no code change. A real regression moves more than one run.

The actor expansion (4 → 20 cases) is the mirror image of the coach one: the score went **up**, so the old 4 cases were thin rather than wrong, and no new failure class appeared. The value was in what it surfaced outside the score — OPEN-12.
